# v1.0.0 — Angular Template pronto para produção

v1.0.0 é o primeiro baseline production-ready do template.

## Destaques

- baseline Angular 22.2.x / TypeScript 6.0.x strict e standalone;
- arquitetura feature-first com enforcement automatizado de fronteiras cross-feature;
- integração HTTP/API same-origin tipada com correlação e Problem Details;
- modo mock local sem infraestrutura;
- modo BFF opcional com fronteiras de sessão, XSRF, CORS e responsabilidades documentadas;
- testes unitários Vitest e contratos de browser Playwright em modos mock/BFF;
- cobertura mínima de 85% para statements, branches, functions e lines;
- ESLint, Prettier, npm audit, CodeQL, Codecov com GitHub OIDC, CodeRabbit, Dependabot, OWASP ZAP e checks de segurança frontend;
- observabilidade vendor-neutral com fronteira opcional de exporter OpenTelemetry;
- validação de bootstrap limpo a partir de uma cópia isolada;
- comentário de status do CI no PR identificando gates falhos/skipped;
- documentação completa bilíngue English/pt-BR de primeiros passos, arquitetura, HTTP, testes, qualidade, segurança, observabilidade, CI, BFF, contribuição e política de segurança;
- validação automatizada da paridade de documentação e badges de status/toolchain no README.

## Bootstrap

```bash
nvm use
npm ci
npm start
```

Nenhuma infraestrutura externa é necessária no modo padrão de desenvolvimento.

## Validação

```bash
npm run ci:verify
```

O repositório também expõe `npm run bootstrap:verify` para validar instalação e build de produção a partir de uma cópia temporária limpa.

## Compatibilidade

A release é validada com Node.js 24.15.0+ na linha Node 24, junto da toolchain Angular 22.2.x e TypeScript 6.0.x resolvida pelo lockfile versionado.

TypeScript 7 não é forçado nesta release porque as faixas de compatibilidade atuais de Angular/build/lint exigem TypeScript 6.0.x.

## Distribuição

v1.0.0 será distribuído inicialmente como GitHub Template Repository. A distribuição via npm/Angular Schematics está planejada como evolução pós-v1.0.

## Notas de upgrade

Não existe requisito de migração a partir de uma release estável anterior. Consumidores pré-v1 existentes devem comparar suas customizações locais antes de adotar o baseline v1.0.

## Processo de release

Crie a tag `v1.0.0` apenas depois que o PR v1.0 for mergeado e CI + CodeQL estiverem verdes em `main`.
